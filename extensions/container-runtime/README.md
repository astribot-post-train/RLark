# RLark container-runtime extension

This is an independently buildable Go module for moving Docker and Raw runtime implementation out of the native RLark module. Its API uses the `containers.rlark.io/v1alpha1` group and companion resources pinned to native object UIDs. It reuses RLark's exported execution contracts; native RLark remains a versioned dependency and contains only generic ownership dispatch.

Current contents are an extraction copy of preview Docker/Raw runtime, allocation and supervisor packages, typed companion API/CRDs, UID/tenant binding checks, and a validation-only controller. The companion allocation package implements an API-backed exclusive per-native-Node lock, exact-UID recovery, legacy reservation fencing and cleanup-confirmed release. It is not yet connected to a Job scheduler or Agent cleanup reporter, so it does not make the module a working scheduler. The controller verifies native Cluster, Node and Job references; it deliberately does not schedule work, mark Agent registration ready, publish artifacts, or permit deletion while companion nodes remain. Native Jobs that declare `rlark.io/controller-owner: containers.rlark.io` fail closed if the extension owner is not installed. Production Agent enrollment/heartbeat, allocation dispatch, cleanup status/reporting, release hosting/rollout, UI and safe live-data migration remain incomplete. Do not deploy this module as a production scheduler.

Run `make test`, `make vet`, `make build`, or `make generate-crds` here. `GOWORK=off` is used to prove the module resolves from its own `go.mod` and `go.sum`.

The detailed target, rollout, cloud test constraints and acceptance gates are maintained in the paired RLark developer plan at `../../apps/rlark/docs/developer-guide/raw-container-runtime-plan.md` and its Chinese counterpart.
