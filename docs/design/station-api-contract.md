# Station API Contract (Experimental)

This contract defines the checked-in `station.rlark.io/v1alpha1` types and generated CRDs in `extensions/station`. The five Station identity CRDs have a local development deployment; they are not production-ready. The `NodeOperation` CRD is installed in the KCP root workspace, and its controller is running with the opt-in flag in the local development cluster; live Join/Remove remains under test.

## Scope and namespace mapping

The five Station identity resources and `NodeOperation` are namespaced. A trusted registration maps one stable cluster ID to one member Kubernetes API client and one `Cluster.spec.agentNamespace`. The namespace is a placement boundary, not the cluster identity. Registration must reject two active cluster registrations that claim the same namespace. The stable cluster ID is recorded in `StationSequence.spec.clusterID` and resolved server-side; request namespace or labels alone never prove membership.

## Resources and ownership

| Resource | Writer | Contract |
| --- | --- | --- |
| `Station` | `station-controller` | Long-lived identity. `metadata.name` is a deterministic 128-bit ID derived from the trusted cluster ID and verified Node UID; it is stable for duplicate/retried discovery and is not an authentication credential. `metadata.uid` identifies the Kubernetes object instance. Spec owns display name, per-cluster sequence, current Node name/UID binding, binding version and irreversible retired desired state. Status owns phase, boot time, last seen time and conditions. |
| `StationObservation` | `station-api` | One replaceable latest snapshot per verified Node name. API creates the namespaced object with an empty `spec`, then writes the snapshot through `/status`. Server-owned annotations bind it to Cluster ID and Node UID; Station object UID is absent during bootstrap and added once a current Station exists. `status.reportedAt` is server receipt time; client clocks are not used for liveness. The current Node UID is stored with each snapshot so a same-name replacement cannot be mistaken for the previous binding. |
| `StationSequence` | `station-controller` | One allocator per registered cluster. `status.lastAssigned` advances with resourceVersion compare-and-swap; gaps are allowed and values are never reused. `spec.clusterID` is immutable. |
| `StationRebind` | Administrator Gateway endpoint, then `station-controller` | Immutable one-shot operation with a stable request ID, exact Station object UID, expected binding version, target Node identity, authenticated requester and reason. The admin-only Gateway endpoint resolves the Cluster namespace, checks the displayed Station UID/version and derives a deterministic operation name. A retry with the same request ID and payload returns the existing operation; the same ID with different content is a conflict. The controller independently verifies the target Node UID from the member API. Before changing Station Spec, the controller records `status.previousBinding`; status then moves through `Accepted`, `Applied` or `Rejected`. Operation status is not an audit log. |
| `StationAuditEvent` | `station-controller` | Immutable append-only security record created separately from Rebind status. Its deterministic name derives from the operation object UID. Create retries compare the stored event and reject a conflicting payload; the first server timestamp is retained. Runtime RBAC grants create/get only, not update/delete. |
| `NodeOperation` | Administrator Gateway endpoint, then opt-in `station-controller` | Experimental one-shot Join/Remove operation with stable request ID, registered Cluster ID, exact Node UID for removal, and an operation-owned short-lived credential Secret. Join refuses existing kubeadm state unless `resetExistingKubeadm` is explicitly set; then the controller verifies the requested Node name and hardware system UUID are absent from the target cluster and the SSH-verified host is not a control plane before an operation-marked, non-replayed reset. This check does not inspect other clusters. Remove requires a UID-owned or observation-verified WireGuard config entry, waits for the network DaemonSet Pod to stop, then resets and deletes only the exact Node UID. No WG peer allocation is implemented. Live Join/Remove has not yet been accepted end-to-end. |

`StationObservation.status.wireguard` is a latest-state snapshot, not desired peer configuration. The optional `publicKey` is the public key for the observed interface, read from the kernel by `station-gateway` and forwarded by the identity agent. It is validated as a 32-byte WireGuard public key and stored alongside the interface and addresses. Old agents may omit it. The field is public observation only: it does not authenticate a Node, authorize a peer change, or expose peer keys, endpoints, AllowedIPs or any private key.

Every resource uses the registered cluster's `agentNamespace`; no resource is cluster-scoped. Node name, system UUID, labels and source IP are supporting evidence only. An initial heartbeat may be accepted after server-side TokenReview and fresh Pod, ServiceAccount and Node reads before a Station exists; this lets the controller create the first Station. That bootstrap observation is owned by the verified cluster ID and Node UID only. Once a Station binding exists, its current object UID and binding version are required for challenges and sensitive operations. A Node UID change does not trigger automatic adoption.

## Validation and lifecycle

Generated CRD schemas enforce bounded strings and lists, positive binding versions and Station sequence numbers, non-negative probe latency and phase enums. CEL rules make Station display name and sequence immutable, require each changed binding to increment its version once, keep the sequence cluster ID immutable and non-decreasing, and make rebind request specs immutable. The API server remains authoritative for schema validation; clients must not rely on UI checks.

Observations are latest-state snapshots, not history. The API must enforce request size and rate limits before writing and authorize each observation against fresh member-cluster identity. If no Station exists yet, only the ordinary heartbeat endpoint accepts the verified Node identity; no sensitive operation is available. After Station creation, the API additionally requires the current Station UID and binding version. The controller derives `Observed`, `IdentityMatched`, `RLarkLinked` and `NetworkVerified` conditions from current resources and timestamps. `ObservedGeneration` is set only for Spec-driven results and must not be treated as a blanket freshness rule for external health.

Retirement is durable desired state; a retired Station is not reactivated by a heartbeat and CEL prevents reversing retirement. The API has no hard-delete endpoint. Retention of old Rebind operations and audit events, Station deletion/finalizer policy, and observation cleanup after a Node rename remain explicit design questions before production installation.

## Controller prototype

`StationReconciler` reads only current Observations within a unique `Cluster.spec.agentNamespace` mapping, derives a deterministic Station name from cluster ID and verified Node UID, allocates a never-reused sequence through status compare-and-swap, and refreshes Station conditions from the current snapshot. A duplicate Node UID or duplicate Node-name binding is marked Conflict. A same-name replacement does not change the old binding or create a replacement Station. The 90-second freshness threshold is strict: at exactly 90 seconds the station is Offline. Missing observations preserve the binding and mark the Station Offline. Status writes use a fresh API reader and bounded conflict retries.

`RebindReconciler` first stores the prior binding snapshot on the immutable operation status, then verifies the target Node against the registered member API and conditionally advances the binding version exactly once. It writes `StationAuditEvent` before making the operation terminal. Concurrent duplicate reconciles recognize the same already-applied target and converge on one audit event. If the process stops after changing the binding or audit storage is unavailable, the operation remains Accepted and retries; a repeated event create must be idempotent. The controller entrypoint and example RBAC/Deployment exist, but production kcp identity and permissions have not been validated.

Before applying a Rebind, the controller lists Stations in the registered namespace and rejects a target Node UID already bound to another Station, or a request that targets the current binding without a prior operation snapshot. Station discovery and Rebind reconciliation share a context-aware serialized coordinator inside the leader-elected manager, so their list/create/binding transitions do not race in the active manager. Race tests run separate Rebind reconcilers and Station discovery concurrently against one Node UID and verify exactly one owner. Real-API reconciliation and a limited leader handoff test are described below; leader failure during identity mutation remains untested.

The coordinator rejects an already-cancelled context before acquisition and checks cancellation again after acquiring the gate, releasing it if cancellation raced with acquisition. A regression test covers cancellation with both a held and a free gate, followed by successful acquisition by another caller. Cancellation after acquisition remains the reconciler's responsibility: its API operations receive the same context. This process-local gate is not a distributed fencing mechanism.

On 2026-11-11 an opt-in controller integration test ran against five CRDs in a disposable kcp workspace. A real Observation status drove Station creation and repeated reconciliation; a Rebind advanced the binding once, recorded its prior binding and one Kubernetes audit event, and became Applied. Retirement succeeded and reversal was rejected. The first run revealed that the CEL retirement rule accessed the omitted optional `retired` field during status updates; the source rule now checks field presence, and the regenerated CRD passed the full test. The workspace was deleted. The test invokes reconcilers directly with a fake registered-cluster resolver and member Node verifier; it does not test manager leader election, member credentials, production RBAC or deployment.

The same real-API test now injects an audit outage after the binding update. It verifies that the operation remains nonterminal with the previous binding persisted, reconstructs the reconciler and coordinator, and retries against the real Kubernetes audit sink. The binding version remains unchanged on retry, exactly one audit event exists, and the operation becomes Applied; a subsequent retry remains idempotent. The race-enabled test passed in a disposable kcp workspace, which was deleted. Reconstructing these in-process objects is not a manager leader-failover test.

Station sequence, binding and status patches now include an explicit resourceVersion precondition; plain merge patches did not enforce the intended compare-and-swap. An isolated kcp test verified a stale sequence update is rejected and six independently coordinated concurrent Station creations receive distinct sequence numbers. The test workspace was deleted. This protects updates to the same object; uniqueness across different Station objects still relies on the active manager's coordination and is not distributed fencing.

In a separate disposable kcp workspace, two controller-runtime managers with a shared Lease and shortened test durations competed for leadership. After the first manager was gracefully cancelled, the other acquired leadership; the leader-only probe observed no overlap. The race-enabled test passed and the workspace was deleted. This checks graceful manager handoff for a cooperative probe, not process killing, network partition, a stalled old leader, production timing or Rebind/Station reconciliation during failover. Kubernetes leader election and the process-local coordinator are not a distributed fencing guarantee.

The target Node reader obtains kubeconfigs from management-plane Secrets named `MemberKubeconfigSecretName(clusterID)`, whose `station.rlark.io/cluster-id` annotation must match. It copies Secret data into memory, uses client-go TLS verification, reads the current Node on every operation, and replaces its cached client when the Secret content changes. No member host receives a config file. Restrict the controller's Secret access to the dedicated credential namespace; each stored kubeconfig still needs member-side least-privilege RBAC for Node reads. The sample Deployment mounts its management API kubeconfig from a Secret inside the Pod; the Secret is not included, and production kcp authentication and permissions are not validated.

## Current implementation evidence

`extensions/station/api/v1alpha1` contains Go types, scheme registration and generated deep-copy methods. `extensions/station/config/crd/bases` contains five CRDs generated with the repository-pinned `controller-gen v0.18.0`. On 2026-11-11, all five CRDs installed and reached Established in a disposable kcp workspace. Admission accepted valid Station, Sequence, Observation, Rebind and AuditEvent objects; Observation status and Rebind `previousBinding` status writes succeeded. CEL rejected Station display-name changes, binding changes without exactly one version increment, retirement reversal, sequence decrease, Rebind spec mutation and AuditEvent spec mutation. The workspace and temporary kubeconfig were removed. This does not prove APIExport/APIBinding permissions, production RBAC or manager rollout; those remain to test before installation.

The Station controller library has a manager entrypoint, container and RBAC/Deployment manifests; the local development cluster currently runs the Station API/controller and identity/network DaemonSets. The RLark identity package includes a Kubernetes Observation sink and a dynamic registry prototype. The sink resolves the unique current `Cluster.spec.agentNamespace`, creates an empty Observation before writing status, and stores cluster/Node UID ownership. The first verified report can bootstrap a Station; after the controller creates it, a later report binds the Observation to that exact Station object UID using a separate resource-version-guarded metadata patch before updating status. A different Cluster, Node UID or already-recorded Station UID is rejected. The registry reads the current Cluster and a dedicated annotated member-credential Secret, refreshes its member API client after kubeconfig rotation, and resolves the current Station binding before every authentication. The `station-api` executable serves HTTPS, uses a durable PostgreSQL challenge store, writes validated Observations, bounds request rate, and separates liveness from dependency readiness. Race tests cover duplicate and concurrent observation reconcile, UID conflict, exact timeout and recovery, missing observations, retired state, sequence ownership collision, readiness dependency failure recovery, Rebind version and Station-UID conflicts, audit outage recovery, concurrent duplicate Rebind requests, and the identity registry/sink bootstrap, rate and ownership behavior. A handler-level fake Kubernetes test covers initial Observation, Station creation, UID binding and challenge issuance as one sequence. Production kcp authentication, exact RBAC grants, credential Secret provisioning/rotation, external TLS endpoint and certificate validation, audit query authorization, live CRD status writes and production sensitive-action policy remain to validate. NodeOperation CRD and controller are installed in the development topology; Join/Remove end-to-end has not yet been validated. The Gateway administrator Rebind endpoint is covered by fake Kubernetes and JWT authorization tests.

Run `GOWORK=off go test ./...` and `GOWORK=off go vet ./...` from `extensions/station`. Regenerate with the pinned generator, not a different controller-tools version.
