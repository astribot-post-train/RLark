# Fleet Dashboard PostgreSQL 迁移设计（进行中）

## 当前证据与边界

`fleet/src/fleet/dashboard/state.py` 直接使用 SQLite，默认 `:memory:`；操作、事件在 SQLite 中，worker 注册表在进程内。`create_app` 在启动时将所有 running 操作标记为 unknown，适用于单持有者，不可直接用于多实例。现有 PostgreSQL 15 实例由 RLark 使用；生产容量、备份、恢复目标和访问权限尚未核对。不要把一个实例启动当作其他实例死亡，也不要把切换存储等同于迁移机器人控制权。

2026-11-11 已修复 Fleet Dashboard 单持有者 SQLite 模式的一处不确定结果处理：带请求 ID 的 runner 动作在预留后抛出 KeyError、RuntimeError、ValueError 或 OSError 时，操作记为 unknown，避免将可能已经执行的动作误记为 failed。测试验证关闭并重新打开 SQLite 后，相同请求不会再次派发，不同动作复用 ID 返回冲突。该修改尚未部署，不实现 PostgreSQL、多实例租约或远端动作结果查询；无请求 ID 仍无此保护。

## 目标接口与数据

- Dashboard 保留现有操作、事件和 HTTP 返回契约。新增显式 PostgreSQL 数据源配置，连接凭证只通过部署 Secret 注入；必须验证 TLS、连接超时和健康状态，禁止输出 DSN 中的密码。SQLite 继续作为单进程兼容模式，不能用于多实例共享。
- 创建 Fleet 专用数据库和最小权限账号，使用版本化迁移；不复用 RLark 应用数据库账号。操作以稳定 operation ID 为主键、request ID 唯一，持久化请求指纹、状态、目标、创建/更新时间、持有者和租约到期时间。状态和事件的事务边界明确，已提交结果可重读，外部动作未知时标记 unknown，绝不自动重放。
- `begin_operation` 在数据库事务中原子占用 request ID；并发相同请求返回同一操作，不同指纹报冲突。持有者使用唯一实例 ID 和数据库服务器时间续租；仅条件更新过期租约且版本匹配的记录，恢复成 unknown，避免重启实例影响其他活跃实例。失联和响应丢失都需要幂等测试。
- 同一事件流所有写事务先锁定对应 `event_counter` 行并递增，再写事件，持锁至事务提交；消费者只能推进到已提交事件，保存独立消费者游标，确认和幂等处理须明确。批量插入在同一锁和事务内分配连续编号；删除或归档须考虑未追上的消费者。不同流可独立锁定；吞吐瓶颈和消费者停滞需指标与容量测试。
- worker 活跃状态使用明确的租约及心跳，稳定业务 ID 与实例 ID 分离；Dashboard 当前进程内 worker 表不自动变成持久成员目录。采集文件保留 NAS，数据库只保存事务化元数据、完成状态和校验摘要；不得把本地缓存关闭等同于远端持久化。

## 2026-11-11 当前实验接入边界

显式注入的 `ExperimentalPostgresDashboardState` 已将 runner 路由、操作查询、历史、事件和 worker descriptor 统一接到 PostgreSQL，并启动有界恢复循环。schema v2 可事务化升级实验 v1，并增加以稳定 worker ID 为键、区分 instance ID、generation 和数据库时间租约的 registry；并发新实例只能在旧租约过期后接管。过期 descriptor 保留并标记 `lease_active=false`。registry 尚未接入公开 `/api/workers` 路由，该路由仍从已连接 Driver 读取。默认 Dashboard 仍使用 SQLite，未提供环境变量切换，也未部署。

`DriverAdmission` 是下一层实验性准入原语：它把一次性签名凭证绑定到操作、持有者、代次、动作、资源、路径和请求体摘要，并在数据库中原子消费。它仅在显式注入的实验模式接入 `driver_app.py` 的 stop 路由，已通过显式注入的实验路径接入 `DriverHTTPClient` 的 stop 调用，因此当前不能声称旧进程或真实 runner 已被 fencing。接入前必须让 driver 持久化并验证准入消费，处理凭证轮换、数据库故障和已有动作；失败时只能拒绝新动作，不能假设已接受动作停止。

2026-11-11 Driver HTTP 隔离接入：显式注入准入门时，仅 `POST /v1/runners/{id}/stop` 可凭一次性凭证通过，其他 HTTP 写入拒绝；使用假 driver 和隔离 PostgreSQL 验证有效请求仅执行一次、缺失/篡改/重放/其他路径及数据库故障均在动作前拒绝。完整相关测试 40 项通过，补充故障测试通过，测试容器已删除。默认 Driver 未启用；实验性 Dashboard 客户端现可为 stop 签发并发送凭证，读取认证、其他动作、已运行任务终止及实际机器人安全仍未覆盖。

2026-11-11 实验性 stop 端到端：显式注入 Dashboard 适配器与 Driver 准入门，使用隔离 PostgreSQL、本机 HTTP 和假 Driver，验证预留、签名、一次性消费、终态写入及相同请求去重；假 Driver 只执行一次，其他动作在该模式被拒绝。相关测试 40 项和 lint 通过，测试容器已删除。该路径没有配置入口或部署，本机 HTTP 不代表生产安全，真实网络 TLS、密钥轮换、生产授权、其他动作及已接受任务的 fencing 尚未验收。

2026-11-11 核对真实 Driver 返回格式后修正实验派发器：stop 返回 `stopped` 且 `reusable=true` 时，操作记为 completed 并保留原始详情；其他未识别结果仍为 unknown。隔离端到端测试另模拟 Driver 执行后响应丢失，操作记为 unknown，相同请求重试不再执行；40 项测试与 lint 通过，测试容器已删除。实际远端结果和机器人安全仍未验证。

## 迁移和恢复

1. 盘点每个 Dashboard 实例的实际 SQLite 路径、版本、运行中操作和 JSON 元数据；确认数据所有权及可备份副本，不能以示例路径代替清点。记录演练前后的计数、主键、引用和摘要。
2. 在隔离数据库完成 schema、权限、并发和恢复测试。以幂等导入工具迁移历史；切换时停写并备份原数据、导入核对，再将所有实例切到单一写入源。操作结果不明的记录标记 unknown；恢复或回滚不得重放动作。
3. 切换后如果需要回滚，先停止新写入并导出 PostgreSQL 增量再决定如何保留，不能直接恢复旧 SQLite 而丢弃新增记录。按约定 RPO/RTO 演练备份恢复、数据库重启、断链和实例强杀；RPO/RTO、生产容量和凭证轮换由运维确认。

## 验收矩阵

- 两个及以上独立进程并发同一 request ID：同指纹只产生一个操作，不同指纹稳定冲突；事务提交成功但响应丢失后重试不重复外部动作。
